# 平遥online

用 Three.js 从第一人称探索平遥古城和四面城墙外的县城街区。当前范围以古城为中心，约 5 公里见方。

直接用浏览器打开「平遥online.html」，或运行 `npm run dev` 后打开 http://127.0.0.1:4173。页面首次加载 Three.js 需要能访问 jsDelivr，无需安装 npm 依赖。

点击场景或「开始体验」进入场景。支持 Pointer Lock 的浏览器会锁定并隐藏光标，移动鼠标直接转头，Esc 退出体验。体验入口与锁定权限分离：API 缺失、请求拒绝或 1.8 秒无结果时仍可进入，明确显示「兼容体验」，按住鼠标拖动转头，WASD / 方向键可用，光标保持可见；可以点击「重试锁定鼠标」。这不是假装锁定，也无法绕过宿主浏览器的权限限制。普通移动、查看地标和 blur 不主动解锁，浏览器或操作系统收回捕获时同步退出。触屏保留拖动与方向键。标题、按钮、辅助描述统一使用“平遥online / 体验”，不显示准星。

## 数据与模型

- [OpenStreetMap contributors](https://www.openstreetmap.org/copyright)，ODbL。地图快照于 2026-11-25 获取，经纬度边界为 112.153–112.210°E、37.181–37.227°N。项目使用其城墙轮廓、六处城门、道路、部分建筑轮廓、铁路线、水系和公园数据。转换后的几何在 `dist/map-data.js`。
- 普通建筑的形状、位置和高度在没有地图数据的区域为程序生成的近似效果。下西关街采用简化高程，其余区域保持简化地形，城门通道在瓮城附近做了简化。视角可穿越建筑，本项目用于浏览。
- [UNESCO 世界遗产中心 · 平遥古城地图](https://whc.unesco.org/en/list/812/maps/) 是古城格局的参考资料。
- [Pingyao City walls - China](https://sketchfab.com/3d-models/pingyao-city-walls-china-8e09151d99a148159599fbb37589d05b)，Lionel / Sketchfab，CC Attribution。在「资料与模型」中通过官方嵌入视图独立展示。

代码改动后运行 `npm run check` 检查模块，再运行 `npm run build` 更新单文件版本。更新地图时，下载相同范围的 OSM XML，再运行 `python3 scripts/import_osm.py 路径.osm dist/map-data.js`。

## 古城核心地标 · 第一期

在地标资料面板点击「前往这里」进入观察机位。锁定鼠标时，将视线朝向建筑再单击可以查看介绍，首次点击进入控制不会同时弹出介绍；暂停后也可点击名称标签。锁定时点击地标显示不打断体验的介绍浮层；Esc 退出后可以打开完整资料面板。

- 城墙：保留原始 OSM 不规则轮廓、南墙曲折、马面轮廓和六处城门；新增收分墙体、步道、两侧垛口、拱洞、重檐城楼和四处角楼。马面来自已有轮廓，不另按固定间距虚构。墙体截面、角楼形式、瓮城门洞均为近似。
- 市楼（金井楼）：用户确认的“钟楼”对象。基底采用 [OSM 1420388662](https://www.openstreetmap.org/way/1420388662)，高度 18.5 米，保留南北过街通道、三重檐和黄绿琉璃特征。木柱、斗拱、栏杆、屋脊为独立几何。屋面及细部比例是近似，不是测绘级复原。
- 日昇昌：采用 [OSM 文保地块 1448309648](https://www.openstreetmap.org/way/1448309648)，表现朝北的三进主院及侧院。文保范围不是每栋房屋轮廓；21 座原建筑未逐一测绘，当前布局和尺寸为近似。形制参考[中国文化研究院](https://chiculture.org.hk/en/node/3463)与[日昇昌旧址资料](https://bkso.baidu.com/item/日昇昌旧址/12766253)。
- 县衙：依据 [OSM POI](https://www.openstreetmap.org/node/2372889878)、[亲民堂](https://www.openstreetmap.org/way/353940320)及三处附属建筑的定位，表现六进中轴和两侧院落。112 × 205 米总边界是推定建模范围，不能作为真实权属边界；其余建筑位置和立面近似。
- 文庙：采用 [OSM 文保地块 711977279](https://www.openstreetmap.org/way/711977279)，表现棂星门、泮池、大成门、五开间单檐歇山大成殿及后院。殿宇间距、尺寸与内部布局未获测绘图，为近似。参考[公开建筑介绍](https://chiculture.org.hk/sc/china-five-thousand-years/3460)与[文庙资料](https://zh.wikipedia.org/wiki/平遥文庙)。

### 坐标和资源

本期保留的原始坐标、OSM 对象版本与更新时间在 `dist/landmarks/survey.js`；地标的坐标、来源、精度声明和观察机位在 `data.js`。数据来自项目原有 2026-11-25 OSM XML 快照，按 ODbL 署名使用。坐标都是 WGS84，使用 `coordinates.js` 转换为与现有地图一致的局部米制坐标：原点 `(112.1815, 37.204)`，X 向东、Z 向南。GCJ-02 必须显式传入 `geographicToLocal(coordinate, 'GCJ-02')`，不重复转换现有局部地图数据。GCJ 数学转换是近似算法，不代表官方测绘精度。

当前仓库高德功能是外部地图查询链接，不包含运行中的高德底图 SDK；本期没有更换地图或注入 Key。五个地标都明确标为近似复原。市楼、县衙、文庙使用独立细化几何模块，尚未接入测绘/扫描 GLB；既有 Sketchfab 嵌入仅供独立查看，并非场景模型资产。

### 模块和验证

实际源码位于 `dist/`，`src/` 当前为空。`LandmarkManager.js` 管理独立加载、卸载、资源释放、点击拾取和标签；`architecture.js` 提供曲面屋顶、屋脊、立柱、斗拱、窗棂及材质。`model.js` 仅让出城墙和地标地块；`city.js` 保留原有控制器，添加管理器初始化和每帧标签更新。普通建筑生成器会避让地标范围。

构件按材质与细节级别合并，五处地标共 55 个网格、约 58.3 万三角形（含近景细节）。距建筑 260 米以上隐藏瓦垄等细节；城墙细节在高度 180 米以上隐藏。沿用原有静态阴影刷新策略，不增加每帧阴影渲染。几何数量是 CPU 统计，并非目标电脑帧率承诺。

修改期间无需开启编译监听。完成一批代码后依次运行 `npm run check`、`npm test`、`npm run build`，最后打开单文件。`npm run dev` 只是静态 HTTP 服务，不监视也不自动编译。坐标、GCJ 往返、地块、OSM 轮廓一致性有自动测试。`tests/geometry.mjs` 另验证高度、通道、遮挡拾取、LOD、加载卸载与几何预算，需要将 `three` 映射至页面同版本 0.180.0；不为此修改生产依赖。

### 西关街至城门和剧场

下西关街沿途加入不同层数、窗型、卷帘门、玻璃门、雨篷、柜台和路灯。地图只有部分门牌和建筑轮廓，连续铺面为手工规则生成，未核实的店名不上招牌。下西关街两段道路来自 OSM，贯通永安北路口、顺城路和郑孝燮路。人行道宽度和沿街铺面尺寸为示意。移除了位置未经验证的邮储招牌、路牌和凤仪门牌匾。凤仪门按[平遥古城保护性详细规划](https://www.sxghy.cn/detail/index/21?detailId=234)所述改为南向瓮城外门，进入后再折向内门。门洞尺寸及铺装为示意。

又见平遥利用 [剧场地图轮廓](https://www.openstreetmap.org/way/1313449886)和[公开外观照片](https://www.sohu.com/a/681908732_142447)，做了夯土、瓦顶、票务门洞和入口广场，可搜索进入低空或高处查看。模型覆盖外观，没有剧场室内和演出内容。

街景搜索中的「在高德核对」打开高德官方 [URI 搜索](https://lbs.amap.com/api/uri-api/guide/embedded-map/search-result)，无需在项目中配置 Key。它用于独立核对，项目未调用或存储高德 Web 服务 POI 查询结果。

### 下西关街商户核对

2026-11-25 用高德 POI 2.0 多边形搜索查询下西关街两侧，共使用 4 次请求，每页 25 条。去重后得到 100 条地图记录，67 条有导航入口字段，25 条有父级地点字段。查询范围只覆盖街道两侧，返回内容也包含商场内商户、路口周边设施及共用导航点。入口字段不能据此认定店面位置和门头顺序。

施工版新增 21 个可搜索的街边店名，用独立绘制的示意门脸呈现。店名按查询结果人工选取，模型坐标按路段粗略对齐。临近同一门牌或导航点、无法确认物理门脸的条目暂不拆成独立店铺。项目不含 API Key，也不包含查询响应原文件。页面的「在高德核对」可以打开高德搜索，查看对应商户的现行条目。

### 下西关街路面

[Copernicus GLO-30](https://doi.org/10.5270/ESA-c5d3d65)提供约 30 米分辨率的地表高程。项目沿下西关街采样并平滑，得到约 2 米的推算纵向起伏。这个分辨率无法区分精确路面坡度、路缘或每个井盖，也可能受到周围建筑影响。路拱、边沟、缘石、人行道砖、路面颗粒和排水设施由项目独立建模。低空移动和离地高度读数跟随该段地形。

可用 `python3 scripts/import_road_elevation.py 高程瓦片.tif 地图.osm dist/west-elevation.js` 重新生成纵坡样本，需安装 Pillow。

## 院落密度、石板路与宇峰写字楼街坊

2026-11-25 根据提供的街景照片，将古城道路与院落从偏黄纯色改为灰色长方石板，加入错缝、浅磨损、细微暖灰色差及凹凸。纹理按世界米制坐标铺设，单块约 0.8 × 0.4 米，不随路段长度拉伸。照片仅用作风格参考，不把照片内商铺复制成新地点。

`old-town-layout.js` 在道路之间生成大院与小院两轮填充：当前为 1,399 个示意院落，包含约 6,995 栋正房、厢房及临巷房屋。每院保留空庭、围墙和入口；院落之间留窄巷。仍保留能够放置的沿街房屋，使街边与街区内部衔接。真实道路、河道、城墙、门前空间、OSM 建筑、公园与五个地标保持避让。这里只表达古城连续街坊的密度和形态，并非逐户实测位置。

新增 `yufeng-block.js` 表现宇峰写字楼楼后及北侧街坊：从下西关街进入的后巷、与顺城路相接的支巷、低层商住楼、小院、玻璃门、卷帘门、雨篷、空调、灯杆和停车细节。名称沿用已有高德核对记录的“宇峰写字楼”，搜索兼容“宇锋”。内部道路和房屋轮廓尚缺可靠测绘，已明确标为近似，不给未核实的门脸添加真实店名。

在「搜索街景」中搜索“宇锋”“楼后街巷”“北侧街坊”或“古城灰石板街景”可进入对应机位。新增院落与楼后街坊使用共享几何、实例颜色和合并批次控制绘制成本，不为每块地砖创建独立网格。此次不修改飞行控制；预览与静态服务已关闭，按用户要求不进行浏览器点击测试。修改整理完成后统一检查和打包。

## 表面闪烁修正与下西关街绿化

针对切换视角时地面、屋顶和建筑表面闪烁，保留原相机范围与飞行操作，调整深度缓冲选择：普通 24 位深度环境使用对数深度；仅当支持 EXT_clip_control 且默认深度达到 32 位时使用反向深度，两种模式不同时启用。古城大底面下移，和院落上层铺装保持间隔；天空关闭深度测试与写入，只作为背景。远近细节增加进入/退出距离差，避免在同一临界距离反复切换。参考 [Three.js 相机与深度冲突说明](https://threejs.org/manual/pages/cameras.html)及[渲染器文档](https://threejs.org/docs/pages/WebGLRenderer)。实际闪烁改善和硬件帧率留待用户在原环境验收，未进行浏览器自动点击测试。

`west-greenery.js` 为下西门外至景林江米油糕附近增加行道树、树池、低矮灌木和校门两侧小花池，沿道路两侧人行道布置，避开交叉口、学校及油糕店主要出入口和已知建筑。移除该段原有随机道路树，避免叠加。树冠由分枝和几何叶簇组成，树干、树池及灌木按实例批次绘制。沿街绿化合计 5 个绘制批次、约 68 万三角形；这是 CPU 几何检查结果，不代表实机帧率。可搜索“下西关街 · 绿化步道”直接查看。

卫星核对状态：2026-11-25 访问了 [Esri World Imagery 服务说明](https://services.arcgisonline.com/ArcGIS/rest/services/World_Imagery/MapServer)，一次覆盖道路范围的影像导出请求返回 HTTP 403，未获得可判读图像。这不代表地图无法访问。项目没有嵌入该影像。

### OSM 重新核对与树木细化

2026-11-25 成功通过公开 OSM API 下载下西关街周边（112.158–112.171°E、37.200–37.206°N）数据，含 813 个节点、50 条 way，核对道路和[剧场公园边界](https://www.openstreetmap.org/way/792912478)。`west-green-survey.js` 保存来源、范围及米制公园轮廓，公园模块直接使用此次核对的边界。这一范围没有 natural=tree 节点，因此不把推定种植位置当作实测树位。树位、间距、树种及花池为近似建模，不作为当前绿化状况的实测记录。

### 城外建筑高度依据（2026-11-25）

- 已检查 OSM 原始快照：16 个建筑记录没有 `height` 或 `building:levels`，导入器原来的 6.4 米属于缺省值，不是实测高度。
- 接入 [GlobalBuildingAtlas / GBA.Height](https://doi.org/10.14459/2025mp1782307)，Zhu、Chen、Zhang、Shi、Wang（2025），[CC BY-NC 4.0](https://creativecommons.org/licenses/by-nc/4.0/)。原始栅格 3 米，影像主要为 2019 年、少量 2018 年。这里只保存西侧研究区约 0.5 MB 的裁剪；来源、坐标、摘要及校验在 `data/building-height-provenance.json`。已停止临时的大文件下载。
- `scripts/import_building_heights.py` 将 UTM 49N 栅格通过 WGS84 转为现有局部米坐标，不叠加 GCJ-02 偏移。`west-building-height-data.js` 为量化到 0.1 米的 3 米网格；运行时没有地理库或网络数据下载依赖。
- `building-heights.js` 按每栋楼的占地采样，过滤稀疏异常值后取屋顶高度分位数。明确高度 / 楼层优先；旧遥感只补充较高证据，不覆盖更高的现有建筑估算。楼层支持十几层及更高，不再将城外建筑统一限制为低层。街坊、宇峰后巷和普通道路建筑共用此方法，具名商业楼保留独立体量。
- 该研究区旧栅格最大值只有约 16.5 米，不能证明当前不存在十几层楼，也不足以确认新高楼的位置。此次并未凭空新放十几层高楼；这些楼仍需更新的规划/实测或可辨认的现场资料补全。所有背景建筑高度依旧标为近似，不能宣称已完成当前实景高低楼复原。
- 已重新查看[金辉悦府高德详情与相册](https://www.amap.com/ssr/search/poi_detail?id=B0JK9HEU4J&name=金辉悦府)：可确认其为二中南侧新建电梯住宅，照片呈现多层平顶立面；缺少能确认全区逐栋层数的资料，未把它误判为统一的十几层高楼。
